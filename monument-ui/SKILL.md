# Monument UI

## 法则

炸裂感 = 极简秩序 × 巨大尺度 × 超现实主体 × 真实材质 × 电影光影

不等于：霓虹 + 粒子 + 渐变 + 玻璃拟态 + 20 张卡片。

第一眼要让人产生"这是什么？"的停顿；第二眼他才看按钮和文字。没有这个停顿，就是穿了高级衣服的模板。

但停顿之后，**5 秒内必须看得出这是卖什么的**。看不出，就是炫技，不是设计。

**这些规则只能挡住廉价感，保证不了好看。** 19 条全过、画面却不动人，是常见情况。这时回到锚点和定调重做，不要靠继续抠数字来救。

## 第 0 条：80% 测试（终极判据）

> **把 80% 的装饰元素删掉，这一屏必须依然炸。**

这是唯一一条全局法则，其余 18 条都为它服务。它同时是验收方式和设计方法：

- 设计时：先只放主体 + 主标题 + 一个按钮，这三样必须先成立。成立之后再往回收，而不是先堆满再删。
- 验收时：用 `?bare=1` 打开裸版（JS 里 `location.search` 带 `bare` 时给 body 加 `.bare`，`.bare` 隐藏所有装饰层、粒子、渐变、光晕），截两张图对比。
- 裸版不成立 → 问题在构图和主体，不在装饰。回去换锚点，不许靠加东西救。

**给不出裸版证据，就等于没做。** 能截图就给正常版 + 裸版两张截图；当前环境截不了图，就给出裸版开关代码，并逐项列出裸版里还剩哪些元素、各占多大面积，同时明说"未截图验证"。不许不给证据就写"通过"。

## 何时用 / 何时不用

**用**：Hero、首发页、作品集、活动页、品牌开场、功能单页的展示区；给图像模型写场景提示词。

**不用**（但可借用）：数据看板、后台表格、设置页、需要 30 个以上操作项的密集界面。这类只借"一个主角 + 三层纵深 + 唯一记忆点"，元素上限与留白比例失效。

冲突时必须明说：**"这是操作界面，我用 monument 的层级，但不砍你的必要控件。"**

## 五条硬约束

1. **主角 = 1，且轮廓可读。** 多一个抢戏的主体，重排，不是缩小。截图缩到 200px 宽时，必须还认得出主角是什么。出血只能切掉不影响辨认的部分；切到只剩一面墙，就不叫主角了。
2. **可见 UI 元素 ≤ 30。** 主按钮 1 个，次按钮 ≤ 1 个，其余降为文字链接或收进菜单。
3. **纵深 ≥ 3 层**：前景 UI / 中景主体 / 远景环境，三层亮度曲线单调（通常远暗 → 中最亮 → 前景中间调）。
4. **颜色 ≤ 3 族**：主色 1 + 强调色 1（面积 ≤5%）+ 中性灰阶。黑白灰不算单独一色。
5. **记忆点 = 1 个异常点**：恰好一个现实世界不该存在的东西，落在非视觉重心处，且是唯一不合常理的元素。

## 工作流（先定调，再七步）

0. **定调：重档还是轻档。**
   - **重档**：硬件发布、电影、游戏、品牌事件、作品集、活动页。用 18 个场景锚点，可以暗场、可以史诗。
   - **轻档**：日常工具，比如笔记、记账、协作、社交、效率类产品。用 6 个产品锚点：主角是产品本身的一个实物，保留一个主角、一个光位、有质感的留白和唯一异常，放弃暗场和巨大尺度。
   - 判断不了就问用户。把日常工具硬做成黑色巨碑，第一眼是停顿了，第二眼却看不懂卖什么。
1. **选锚点。** 从 `references/anchors.md` 里按档位挑，或照它自造一个。必须能说出主角的名词和"停顿机制"（尺度压迫 / 物理不可能 / 不该被发现 / 介质错位）。说不出，就是还没准备好。**只写代码、手里没有渲染图时，只能选标了"只有代码时可选"的锚点。**
2. **一句话艺术指导（≤60 字）。** 主体 + 材质 + 光位 + 一个异常。
3. **先搭裸版。** 只放主体、主标题、一个按钮，截图。这一步不成立，后面全白做。
4. **分配重量。** 主角面积：重档 40–65%，轻档 25–45%（产品实物放到 40% 以上，画面会挤，文字没处放）；标题压一侧；留白 ≥30%；主体中线偏移 ≥8%。
5. **打光。** 三盏灯：key（120° 上侧方）/ rim（背后 ±160°，key 的 55–65%）/ ambient（≤15%）。角度怎么量、怎么换算成 CSS 阴影方向，见 `references/material-light.md`。禁止全屏 bloom、禁止到处发光。
6. **上材质。** 只让一个材质做到能看见使用痕迹，其余降到 70%。
7. **回收装饰。** 逐层加回，每加一层问一次：裸版少了它会不会更弱？不会就删。最后跑 `references/checklist.md` 给数字。

## 排版即构图

- 优先两档字号：巨大标题 `clamp(4rem, 9vw, 12rem)`，行高 0.9–0.95，字距 -0.03em；标签、副标、元信息 11–13px。
- 有正文段落时允许第三档：正文 15–17px，行高 1.5–1.6。连续阅读的文字不许用 11–13px，那是标签字号，不是阅读字号。最多三档，不许再多。
- 副标字距 +0.12em 起，全大写或全小写挑一个。**一页最多出现一次"标题上方的小号大写字距标签"**：每个区块都顶一行这种标签，是最典型的 AI 生成味。
- 正文最大宽度 ≤ 34em，一屏最多 2 段。
- 按钮和链接的可点击区域 ≥ 44×44px，哪怕文字只有 12px。
- 标题可以压到主体上（压进受光区或阴影区），它本身就是构图。

## 尺度对比

用停顿机制 A（尺度压迫）时，巨大主角旁必须有极小参照物：一个人、一个按钮、一行 11px 的字。比例 ≥ 40:1。**没有参照物，宏大感不成立**——观众缺一把尺子。

参照物本身也要看得见：在 1280px 宽的截图里至少 8px 高，并且和背景有足够反差。藏进暗处的参照物等于没有。其他三种机制不强制要参照物。

## 动效预算

动效分三类，各算各的预算：

- **入场**：1 次，≤1.2s，`cubic-bezier(.16,1,.3,1)`。
- **常驻**：最多 1 个（呼吸 / 漂浮 / 光移，三选一）。
- **反馈**：每个交互元素都必须有，用户触发才动，不占常驻名额。

全局：同屏同时运动 ≤ 3 个元素；`prefers-reduced-motion` 时去掉位移和循环，只保留状态变化本身。

**状态变化用材质和光来表达，不只是换颜色**：开关打开时光被点亮、液体被吸过去、胶囊里的小场景从白天变成夜晚。强调色只在激活态出现，平时不发光。时长、缓动、六种状态表达方式见 `references/motion.md`。

## 出图模式 vs 实现模式

- **出图模式**（给图像模型写提示词）：用 `references/anchors.md` 的锚点 + `references/negatives.md` 的英文禁止尾巴，每次都带尾巴。不写尾巴，AI 生成味立刻回来。
- **实现模式**（写代码）：不依赖外链图片；用真 3D 或 CSS/SVG 伪造，并老实交代是伪造。代码里的等价禁令见 `negatives.md` 的 B 节。

## 输出格式

0. 定调：重档或轻档，一句话说明理由
1. 锚点（一个名词）+ 停顿机制（四种里选一种）
2. 一句话艺术指导（≤60 字）
3. 构图说明：主体位置、留白比例、三盏灯方位、异常点在哪
4. 裸版截图（或裸版代码开关）
5. 代码（给全，禁止 `// ...` 省略）
6. 自检表：19 条全填实际数字

## 明确拒绝的事

- **"再炸裂一点"** → 不加霓虹粒子。放大尺度、换更硬的材质、压暗环境、扩留白，然后重跑 80% 测试。
- **"多放几个卖点"** → 先问唯一主角是谁；其余降为一行小字或一个切换按钮。
- **"参考某大厂"** → 只提取秩序（网格、层级、光），不复制外观与配色。
